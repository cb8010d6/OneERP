## 1. 当前工程约束

- `Partner` 已承担客户/供应商统一往来单位，后续售前单据应关联 `Partner`，不另建重复客户主数据。
- `Order` 已关联 `Partner`、销售员、税码、明细、工单和发票；新增售前链应保留来源 ID、来源版本和不可变快照，而不是只复制当前值。
- 通用 `Workflow` 当前只支持 `order`、`workOrder`、`invoice` 三类目标。报价、合同和工程文档若复用它，需要显式扩展目标白名单、权限、审计和事件语义。
- `FileRecord` 当前只有公司、上传人和 MinIO 元数据，没有业务对象、版本、校审、批准和发布关系。签署件、图纸和普通附件不能继续只靠目录名表达业务语义。
- 现有销售订单状态包括草稿、待审批、待处理、生产中、部分发货、已发货、已完成和已取消。售前状态不应重复或偷偷改写订单状态。
- D1-D7 已作为业务设计输入；其中标记为“待配置/待技术评审”的内容仍不得在业务代码中写死，也不得据此直接创建 migration。

## 2. 必须确认的业务决策

### D1 客户咨询与商机层级

**已确认：首期只建一张“客户需求单”**，包含来源渠道、需求摘要、预计金额、预计成交日、责任销售、下一次跟进时间和关闭原因；通过状态表达是否已确认商机，不拆 `Lead + Opportunity` 两层。

- 方案 A（建议）：客户需求单一层，适合订单型/项目型制造企业的最小闭环。
- 方案 B：线索 + 商机两层，适合线索池、分配、培育、转商机有明确责任边界的销售组织。
- 方案 C：不建售前对象，直接从客户建报价；最省事，但无法审计咨询和丢单。

确认结果：`采用方案 A；2026-07-10 已确认`

### D2 报价版本与审批

**已确认：允许多版本、多币种和实时换算，不设置报价审批。** 支持有效期、含税/未税、税码、行折扣、整单折扣、交付期和付款条件。对外发出后的版本不可覆盖，只能创建新版本。每个报价版本必须固化交易币种、本位币、汇率、汇率时间和汇率来源，避免后续实时汇率改写历史报价。

- 非 CNY 币种：`需要`
- 报价审批：`不需要`
- 汇率策略：`发出或转单时固定快照；实时汇率服务商待技术评审选择，服务不可用时不得静默使用过期汇率`

### D3 合同登记与订单关系

**已确认：系统维护结构化合同台账并保存签署件；合同与订单为一对多。** 系统不必首期生成法律文本，但应记录合同编号、客户、金额、币种、税价、签署日、生效/到期日、付款条款、交付条款、签署附件和版本。一个框架合同或分批交付合同可生成多个销售订单。

- 方案 A（建议）：结构化登记 + 签署件附件，一份合同可生成多张订单。
- 方案 B：系统生成合同文本并电子签署，范围和合规成本显著增加。
- 方案 C：合同只作为附件挂报价/订单，无法可靠控制履约与版本。

确认结果：`采用方案 A；2026-07-10 已确认`

### D4 图纸校审、发布和旧版本使用

**已确认：设计、校审、批准三权分离；工单固定已发布版本。** 已发布图纸不可覆盖。新工单只能选择当前有效版本；已开工工单默认继续使用其固定版本，如需切换必须走工程变更单并记录影响评估、物料处置和批准人。

- 设计上传岗位：`工程设计`
- 校审岗位：`工程校审`
- 发布批准岗位：`工程负责人/授权批准人`
- 校审人与设计人是否必须不同：`必须不同`
- 已开工工单能否继续使用已作废旧版：`仅经偏差批准后允许`

### D5 生产模式与首期制造深度

**已确认：按混合生产设计，首条验收链先走按订单生产（MTO）。** Phase 4 首期实现工艺路线、工序、工作中心、逐工序人员/工时、领退料、报工、质检、良品入库和外协工序的最小闭环；复杂 APS 延后。

- 实际模式：`混合生产`
- 首期是否有外协工序：`需要`
- 首期是否必须记录每道工序工时和人员：`需要`
- 质检策略：`按产品/工序配置全检或抽检`

### D6 缺料到采购的控制单据

**已确认：缺料可以直接生成采购订单，不增加采购申请。** 自动缺料分析必须先展示供应商、价格、数量和交期预览，由有采购权限的人员确认后创建；不得后台静默承诺供应商，也不得重复转单。

- 采用方案 B：`缺料 -> 采购确认预览 -> 采购订单`
- 询价比价：`不作为直接采购前置门禁，后续可按供应商或金额配置`
- 创建权限：`采购员；无需新增采购申请审批`

### D7 资金管理首期范围

**已确认：首期资金范围纳入预收、预付、费用/其他付款、付款申请与审批、资金账户、日资金视图、员工报销、借款/还款、备用金、银行账户间调拨和多币种。** 分批实施时先复用现有收付款、银行对账和总账内核，不重写已稳定过账流程。

- 预收款、预付款、员工报销、借款/还款、备用金、银行账户间调拨、多币种：`全部纳入`
- 付款审批：`需要；岗位和金额阈值在资金模块实施前配置化确认`

## 3. 建议业务词汇

| 中文名称 | 建议英文名 | 定义 | 首期边界 |
| --- | --- | --- | --- |
| 往来单位 | Partner | 客户、供应商或两者兼具的主体 | 复用现有模型 |

| 销售订单 | Sales Order | 执行生产、交付、开票的订单 | 复用现有 `Order` |
| 工程文档 | Engineering Document | 图纸、规范、工艺附件等受控文档主档 | 区别于普通附件 |

| 采购确认预览 | Purchase Confirmation Preview | 缺料转采购订单前展示供应商、价格、数量和交期的确认视图 | 不新增采购申请实体；确认后直接创建采购订单 |
| 发货单 | Delivery Note | 面向一次或多次实际交付的业务单据 | 与库存流水分层 |

## 4. 建议状态机

### 客户需求单

`草稿 -> 跟进中 -> 已确认 -> 报价中 -> 已转报价 -> 已成单`

任一非终态可进入 `已丢单` 或 `已取消`；丢单必须填写原因。首期不单独建商机时，“已确认”表示需求真实、客户和负责人已明确。

### 报价版本

`草稿 -> 已发出 -> 已接受`

- `已发出 -> 已拒绝 / 已过期 / 已被新版替代`
- 只有 `已接受` 且未过期的版本可转合同或直接转订单；发出和转单必须固定汇率快照。

### 销售合同

`草稿 -> 待审批 -> 已批准 -> 待签署 -> 履约中 -> 已履约`

- `待审批 -> 已驳回`
- `待签署 -> 已取消`
- `履约中 -> 已终止`
- “已签署”动作进入“履约中”，必须绑定签署件和签署日期。

### 工程文档版本

`草稿 -> 待校审 -> 退回修改 / 待批准 -> 已发布 -> 已作废`

- 退回后应创建或继续编辑未发布草稿，不得修改已发布二进制内容。
- 已发布版本发生变更时创建新版本或工程变更单；旧版保留审计。

## 6. 建议编号规则

所有编号按公司作用域唯一，由数据库序列/安全重试机制生成，不使用裸 `Date.now()` 作为唯一性保证。

| 单据 | 格式建议 | 示例 |
| --- | --- | --- |
| 客户需求单 | `REQ-YYYY-######` | `REQ-2026-000001` |
| 报价 | `QT-YYYY-######` | `QT-2026-000001` |
| 报价版本 | 报价号 + `-V##` | `QT-2026-000001-V02` |
| 合同 | `CT-YYYY-######` 或登记真实合同号 | `CT-2026-000001` |
| 合同版本 | 合同号 + `-V##` | `CT-2026-000001-V01` |
| 工程文档 | `ED-产品/项目代码-######` | `ED-P1001-000001` |
| 工程文档版本 | 文档号 + `-R##` | `ED-P1001-000001-R02` |
| 工程变更单 | `ECO-YYYY-######` | `ECO-2026-000001` |
| 发货单 | `DN-YYYY-######` | `DN-2026-000001` |
| 付款申请 | `PAYREQ-YYYY-######` | `PAYREQ-2026-000001` |

真实合同号、客户图号可作为外部编号单独记录，不替代系统内部稳定 ID。

## 7. 端到端验收场景草案

1. 销售为已有客户创建客户需求单，指定责任人和下次跟进时间；其他公司用户不可读取。
2. 销售把需求从草稿推进到已确认，并保留每次跟进时间线；关闭丢单时必须填写原因。
3. 从已确认需求创建报价 V1，客户、明细、税价、交付期和来源 ID 自动带入。
4. 修改价格或条款时生成报价 V2；V1 仍可查看但标记为已被新版替代，历史内容不被覆盖。
5. 销售可直接发出报价；系统必须校验有效期、税价和汇率快照，并记录发出人、时间和送达版本。
6. 报价发出后，系统固定版本快照；过期报价不能直接转合同/订单。
7. 从客户接受的报价登记合同，上传签署件并记录签署日期；未批准合同不能进入履约。
8. 一份合同分两批生成两张销售订单；每张订单可追溯合同版本、报价版本和客户需求单。
9. 重复点击“转订单”或重复请求不会重复创建同一批次订单，幂等结果可审计。
10. 工程人员从订单创建工程文档草稿；普通附件不能冒充已发布图纸。
11. 设计人不能完成自己的校审；未经批准的图纸不能被新工单选择。
12. 工单固定某个已发布图纸/BOM 版本；发布新版本不会静默改变在制工单。
13. 工程变更单批准后，新工单使用新版；受影响在制工单必须明确继续旧版、切换新版或报废返工。
14. 缺料分析先生成采购确认预览；采购员确认供应商、价格、数量和交期后直接创建采购订单，重复确认不产生重复采购承诺。
15. 从合同/订单、发货、开票、收付款到银行流水和总账凭证可以双向追溯，冲销不删除历史。
