## 本轮验收场景

| 场景 | 预期 |
| --- | --- |
| 输入错误登录凭据 | 保留页面与明确错误，不自动刷新其他会话 |
| 公司 A 请求未完成时切到 B | 清空 A 的业务表单与 AI 草稿；A 的响应不覆盖 B，不在 B 重放 A 的写请求 |
| 多请求同时遇到令牌过期 | 共享刷新操作；公司切换不导致同一刷新令牌重复轮换 |
| 查看超出第一页的订单 | 使用服务端总数和分页；搜索/状态变化回第一页 |
| 请求失败或响应乱序 | 明确错误和重试入口；旧响应不覆盖新结果 |
| 桌面键盘操作订单 | 可聚焦的订单入口可打开记录 |
| 通用表单保存引用字段 | 提交外键值，排除展开的关联对象及服务端字段 |
| 敏感系统资源访问 | 使用其专用 API；通用入口及关系查询不绕过边界 |
| 首次体验 / 源码开发 | 入口、独立依赖安装、环境变量、迁移与账号初始化说明匹配仓库实际实现 |

## 验证范围

提交时在 PR 中记录精确验证结果：Prisma 静态校验和生成、API/Web typecheck、lint、单元/组件测试及生产构建。行为测试覆盖延迟响应、公司切换与查询边界，不能替代真实数据库或浏览器验收。

本轮集成结果：`CI=true CHECKPOINT_DISABLE=1 npm run validate` 通过，包含 Root 2、API 490、Web 91 项测试（合计 583）；`npm run risk:preflight` 通过。`npm run audit:security` 在根项目检出 fast-uri / js-yaml 共 2 个 high 告警后停止，后续子项目审计尚未由该命令完成。依赖门禁保持阻断，不将该结果描述为安全审计通过。

本次执行环境没有 Docker/Compose、PostgreSQL 服务与 Graphify；浏览器安装未成功。因此不声明已执行 Docker 启动、真实数据库隔离/迁移、真实财务业务闭环、恢复演练或浏览器截图验收。现有生产门禁继续以 `PRODUCTION_READINESS.md` 和 `GO_LIVE_CHECKLIST.md` 为准。

## 下一轮优先级和完成条件

1. **数据可靠性（P0）**：[#21](https://github.com/cb8010d6/OneERP/issues/21) 将供应商付款/贷项过账与 outbox 写入置于同一事务。必须以数据库故障回滚、幂等重试和并发测试验收。
2. **租户隔离完整性（P0）**：单独核对无 `companyId` 子模型的父级范围与外键归属。通用敏感模型封锁不代表所有业务模型已完成跨租户审计。
3. **受控业务试用（P0）**：在隔离 UAT 的精确提交上验收采购→收货→库存→应付、销售→发货→应收、凭证冲销和试算平衡，并保存报告。不得使用真实生产数据做试验。
4. **发布整合（P1）**：逐项核对 #13/#15 的已实现内容、当前依赖升级 PR 和真实业务验收，拆解剩余风险；保持未完成生产门禁的准确状态。
5. **持续体验（P1）**：统一启动时 `restoreSession` 与 Axios 自动刷新的协调，补真实浏览器桌面/移动截图和员工角色体验。当前只修复已验证的会话与公司切换问题。

新增模块、移动端扩展和大型服务拆分排在上述基础能力之后。本轮不更改生产数据、数据库模型或部署环境。
