# ERP 第五轮迭代交接

日期：2026-09-27。开发、自动验收和真实生产批准是不同的证据。

## 本轮业务结果

- **采购收货**：同一订单行允许拆到不同库位、批次，但总收货量按行累计校验；事务内重新读取剩余数量，防止并发超收。订单进度、收货单、库存和成本流水共同提交或回滚。四位小数贯穿计算，兼容旧客户端浮点减法产生的机器误差。
- **生产冲销**：冲销早先的纯不良品报工时，若净合格数量仍达到计划数量，工单保持已完成。没有改变冲销流水、幂等或会计规则。
- **制造 HTTP 验收**：使用隔离的合成公司，经不同工程角色上传、审核和发布图纸，再创建带版本绑定的工单，核对 BOM 消耗、成品入库、失败回滚、冲销及重放。复用已有临时服务，禁止远端目标和任意已有业务单据输入。
- **账号启用**：新增直接账号与邀请账号统一邮箱格式，已有大小写冲突明确拒绝，不自动合并或覆盖身份。邀请在同一事务中领取并建立账号和成员关系；直接建号前先验证角色授权。管理员初始化在任何写入前检查历史身份冲突。
- **采购工作台**：数据和异步结果归属于公司、用户及权限上下文；切换后不展示旧数据，也不让旧操作解锁新操作。加载失败可重试，保存成功后的读取失败与保存失败分开表达。
- **手工恢复**：复用固定摘要的辅助镜像解包 MinIO 归档，不依赖应用镜像内的 tar；写入数据库前检查归档，SQL 错误停止后续操作。PowerShell 复制 SQL 字节，避免文本管道改变编码。

## 维护与兼容约束

- 采购收货没有新请求幂等键：重复提交部分收货仍是新的业务收货，受剩余数量约束；前端阻止重复点击不能替代服务端数量校验。
- Serializable 只重试已回滚的冲突。提交后的读取失败不允许再次执行收货。
- 历史超收、大小写账号和历史账务不自动修复或补写；必须核对原始业务证据。
- 管理员初始化保留既有规范邮箱账号的 upsert 行为，不应作为修改未知历史身份的工具。
- 恢复 PostgreSQL 与对象存储不是一个原子事务。生产恢复须按运维手册停止写入并在隔离环境演练。
- 未引入运行时依赖、框架迁移或新的会计政策。Graphify 工具与图谱产物缺失，已尝试更新但命令不可用。
